# SensorSim и Collector

Два консольных приложения на C++17 для Windows. SensorSim моделирует датчик,
Collector принимает телеметрию по UDP, сохраняет SAMPLE в CSV и отправляет
команды управления. Обмен происходит только через `127.0.0.1`.

Приложения используют стандартную библиотеку C++, Winsock2 и Windows API для
неблокирующего консольного ввода. Сборка выполняется средствами Visual Studio;
сторонние библиотеки приложениям не требуются.

## Сборка

### Компоненты Visual Studio

Проект проверен в **Visual Studio Community 2026 18.10.2**, конфигурация
**Release x64**, компилятор **MSVC 19.51.36260**, Windows SDK **10.0.26100.0**.

В Visual Studio Installer выбрать **«Разработка классических приложений на C++»**
(*Desktop development with C++*) и убедиться, что установлены:

- средства сборки MSVC C++ для x64/x86;
- Windows SDK;
- **«Средства CMake C++ для Windows»** (*C++ CMake tools for Windows*).

CMake, CTest и Ninja входят в установленный компонент Visual Studio.
Отдельно устанавливать инструменты сборки не требуется.

### Проверенный способ сборки

1. Распаковать архив проекта.
2. Через меню «Пуск» открыть **x64 Native Tools Command Prompt for VS 2026**.
   Эта консоль Visual Studio настраивает компилятор и библиотеки для x64.
3. Перейти в папку `sensor_udp`, содержащую `CMakeLists.txt`, и выполнить:

```bat
cd /d C:\Projects\sensor_udp
cmake -S . -B build -G "Ninja Multi-Config"
cmake --build build --config Release --parallel
ctest --test-dir build -C Release -R "^unit$" --output-on-failure
```

В первой строке заменить `C:\Projects\sensor_udp` на путь к распакованному проекту.
Команды используют компилятор MSVC и встроенные инструменты Visual Studio.
`Ninja Multi-Config` — режим её встроенного сборщика; конфигурация выбирается
параметром `--config Release`.

Результат: `build\Release\SensorSim.exe`, `build\Release\Collector.exe` и
`build\Release\unit_tests.exe`. Последняя команда запускает тесты ядра проекта.
Для новой конфигурации использовать отдельную папку сборки, если `build`
уже создана с другим генератором.

### Работа в окне Visual Studio

Выбрать **«Файл → Открыть → Папка»** и открыть `sensor_udp`.
Visual Studio распознаёт `CMakeLists.txt` и настраивает CMake-проект.
После завершения настройки выбрать конфигурацию x64 и выполнить
**«Сборка → Собрать всё»**. Приложение для запуска выбирается рядом с кнопкой
запуска: `SensorSim.exe` или `Collector.exe`.

Для отладки одного приложения поставить точки останова и запустить его через F5,
а второе приложение запустить в отдельном терминале. Для обязательного демо
ниже удобнее использовать два терминала и файлы из `build\Release` после
сборки приведёнными выше командами. При автоматической настройке через окно
Visual Studio папка сборки может отличаться; её путь указан в выводе CMake.

## Запуск и обязательное демо

Команды запуска выполнять из корня проекта в двух отдельных терминалах
Visual Studio: **«Вид → Терминал»**. Ниже команды для Developer PowerShell.

Терминал 1, сначала запустить Collector, чтобы сохранить первые пакеты:

```powershell
.\build\Release\Collector.exe --csv telemetry.csv
```

Терминал 2:

```powershell
.\build\Release\SensorSim.exe
```

В терминале Collector выполнить команды по одной, дожидаясь ответа:

1. Подождать 2 секунды: появляются SAMPLE примерно каждые 200 мс и HEARTBEAT
   раз в секунду. `telemetry.csv` создаётся сразу, строки сбрасываются на диск
   после каждого SAMPLE.
2. `status` — увидеть rx, loss, loss_rate и возраст последнего HEARTBEAT.
3. `rate 500` — получить `ACK cmd=10`; SAMPLE поступают примерно раз в 500 мс.
   Подождать 2–3 секунды.
4. `fault` — получить `ACK cmd=11`; SAMPLE прекращаются, очередной HEARTBEAT
   содержит `status=FAULT`. Подождать не менее секунды.
5. `rate 200` — в FAULT получить `NACK cmd=10 reason=BUSY`.
6. `reset` — получить `ACK cmd=12`; SAMPLE возобновляются с периодом 200 мс,
   uptime продолжает расти. Подождать 2 секунды.
7. `status`, затем `quit` — завершить Collector. Остановить SensorSim через Ctrl+C.
8. Проверить результат: `Get-Content .\telemetry.csv -TotalCount 10`.

Фактический прогон приложен в `demo/collector.txt`, `demo/sensor.txt` и
`demo/telemetry.csv`. Это вывод реальных процессов сборки Visual Studio/MSVC
с автоматически выбранными свободными портами. В первой строке журнала путь к CSV сокращён.
Отдельный прогон `demo/retry-and-loss.txt` показывает ретрай, тайм-аут,
дубликаты, отбрасывание чужого peer и восстановление пропуска при переупорядочивании.

## Аргументы и команды

| Аргумент | SensorSim по умолчанию | Collector по умолчанию |
|---|---|---|
| `--listen-address` | `127.0.0.1` | `127.0.0.1` |
| `--listen-port` | `24550` | `24551` |
| `--peer-address` | `127.0.0.1` | `127.0.0.1` |
| `--peer-port` | `24551` | `24550` |
| `--period-ms` | `200`, диапазон 50..5000 | не поддерживается |
| `--csv` | не поддерживается | `telemetry.csv` |
| `--run-for-ms` | без ограничения | без ограничения |
| `--help`, `-h` | справка | справка |

Порты: 1..65535, локальный и удалённый порт должны различаться. Разрешён только
буквальный адрес `127.0.0.1`; DNS, wildcard-адрес и внешние интерфейсы не используются.
`--run-for-ms` принимает 1..86400000 и служит для ограниченных по времени запусков.

Пример нестандартных портов и стартового периода:

```powershell
.\build\Release\Collector.exe --listen-port 25551 --peer-port 25550 --csv custom.csv
.\build\Release\SensorSim.exe --listen-port 25550 --peer-port 25551 --period-ms 100
```

| Команда Collector | Результат |
|---|---|
| `status` | Немедленная статистика; также печатается раз в секунду |
| `rate <ms>` | CMD_SET_RATE; 50..5000 применяется датчиком |
| `fault` | CMD_FAULT, прекращение SAMPLE |
| `reset` | CMD_RESET, состояние OK и период 200 мс |
| `quit` | Закрытие CSV и сокета, завершение |

Для проверки NACK консоль допускает число 0..65535 в `rate`; диапазон 50..5000
проверяет SensorSim. Дробные, отрицательные и нечисловые значения отклоняются
в CLI. Неизвестные команды и лишние аргументы не отправляются.

Одновременно ожидается ответ только на одну команду. Следующая команда управления
до ACK/NACK/TIMEOUT отклоняется с сообщением `Command pending`; `status` и `quit`
доступны всегда. Это исключает неоднозначный порядок операций при ретраях.
Ctrl+C поддерживается обоими приложениями. EOF стандартного ввода завершает
Collector; при пакетном управлении нужно держать stdin открытым до получения ответов.
Ввод в консоли поддерживает Enter и Backspace; истории и редактирования стрелками нет.

## Бинарный протокол

Один UDP datagram содержит ровно одно сообщение. Все многобайтовые поля
little-endian, без выравнивания и без сериализации C++-структуры через `reinterpret_cast`.

| Смещение | Поле | Размер |
|---|---|---|
| 0 | magic = `0x53454E53` | uint32 |
| 4 | msg_id | uint16 |
| 6 | seq | uint32 |
| 10 | payload_len | uint16 |
| 12 | payload | payload_len байт |
| 12 + payload_len | checksum | uint16 |

Размер пакета — `14 + payload_len`. Checksum — сумма байт первых
`12 + payload_len` позиций по модулю 65536; это эквивалентно подсчёту с нулевым
полем checksum. Байт-последовательность magic: `53 4E 45 53`.
Float кодируется как IEEE754 binary32 через `memcpy` в uint32, затем побайтово.

| ID | Сообщение | Payload |
|---|---|---|
| 1 | HEARTBEAT | uint8 status: 0 OK, 1 DEGRADED, 2 FAULT |
| 2 | SAMPLE | float temperature_c, float humidity_pct, uint32 uptime_ms |
| 10 | CMD_SET_RATE | uint16 period_ms |
| 11 | CMD_FAULT | пусто |
| 12 | CMD_RESET | пусто |
| 20 | ACK | uint16 cmd_msg_id, uint32 cmd_seq |
| 21 | NACK | uint16 cmd_msg_id, uint32 cmd_seq, uint8 reason |

Датчик генерирует OK и FAULT; Collector также понимает DEGRADED.
Причины NACK: 1 INVALID_ARGS, 2 BUSY, 3 OTHER.

Неверные magic, полная длина datagram или checksum приводят к молчаливому
отбрасыванию и увеличению invalid. Для распознанной команды с корректной оболочкой,
но неверным размером payload, возвращается NACK INVALID_ARGS. SET_RATE с двумя
байтами в FAULT получает BUSY, включая значения вне допустимого диапазона;
в OK недопустимый период получает INVALID_ARGS. Неизвестные ID и сообщения
неправильного направления отбрасываются. Collector проверяет размеры payload,
значения enum и конечность чисел SAMPLE.

## Таймеры, ответы и потери

- Используется `steady_clock`. Температура: `25 + 5*sin(seconds/20)`,
  влажность: `50 + 10*sin(seconds/15)`. При FAULT uptime продолжает расти.
- Первый HEARTBEAT и SAMPLE отправляются сразу. Следующие HEARTBEAT идут
  примерно раз в секунду независимо от SAMPLE и состояния FAULT. Изменение
  периода/выход из FAULT назначает следующий SAMPLE через новый период.
- Каждое новое исходящее сообщение датчика имеет общий seq для HEARTBEAT,
  SAMPLE и ACK/NACK, начиная с 1. Каждая новая команда Collector также имеет
  seq начиная с 1. uint32 seq и uptime переполняются по модулю 2^32.
- Collector ждёт 600 мс и выполняет до двух повторов, всего до трёх отправок.
  Повторы содержат идентичные байты и тот же seq. Ответ сопоставляется по
  паре cmd_msg_id/cmd_seq. После трёх попыток без ответа выводится TIMEOUT:
  команда могла выполниться, результат неизвестен.
- SensorSim хранит последние 64 команды и результаты. Повтор возвращает тот же
  ACK/NACK с новым исходящим seq, не меняя состояние повторно. Если тот же
  cmd_seq повторяется с другим ID/payload, возвращается OTHER. Кеш ограничен:
  очень поздний повтор после вытеснения может примениться заново.
- `rx` — число уникальных принятых корректных телеметрических сообщений,
  включая ACK/NACK. `loss` — пропуски seq после первого принятого сообщения;
  `loss_rate = loss / (rx + loss) * 100%`. Пакеты до старта Collector не учитываются.
  Пропуск временный: пришедший позже пакет в окне 4096 seq уменьшает loss.
  Повторы и слишком старые пакеты не попадают в CSV, их общий счётчик —
  `duplicates_or_old`. Окно занимает фиксированную память.
- Порядок seq определяется модульным расстоянием менее 2^31. После перезапуска
  одного из приложений следует перезапустить оба: протокол не имеет session ID,
  поэтому нельзя надёжно отличить новую сессию от старых пакетов/повторов команд.
- `heartbeat_age_ms` — время от последнего принятого уникального HEARTBEAT,
  либо `never`, если его ещё не было. Поле не является оценкой времени на проводе.

## CSV и ошибки

```text
timestamp,seq,temperature_c,humidity_pct,uptime_ms
```

`timestamp` — UTC время приёма в формате ISO 8601 с миллисекундами, остальные
поля из SAMPLE. Десятичный разделитель всегда точка; порядок строк — порядок
приёма, поэтому при переупорядочивании seq в CSV может уменьшаться.
Файл **перезаписывается при запуске**. Для сохранения разных прогонов указывать
разные имена `--csv`. Родительская папка должна существовать.

Ошибки открытия/записи CSV, сокетов, занятый порт и неверные параметры печатаются
в stderr; код завершения 1. Нормальное завершение — 0. Используется эксклюзивная
привязка к порту. ICMP port-unreachable при отсутствии peer не останавливает
приём UDP. При закрытом SensorSim Collector продолжает работать и показывает
тайм-аут команды/увеличение возраста HEARTBEAT.

Отправитель сверяется с настроенной парой IP:port; чужие пакеты учитываются
в `foreign`. Это фильтрация, а не аутентификация. Checksum обнаруживает простые
повреждения, но не защищает от умышленной подделки. UDP не гарантирует доставку,
порядок и задержку. Планировщик Windows и опрос с шагом до 10 мс вносят задержку;
это симулятор, не система реального времени. Пакетные очереди обрабатываются
ограниченными порциями, чтобы входящий поток не блокировал таймеры и команды.

## Тесты

`unit_tests` собирается без дополнительных инструментов и выполняется CTest
включая Release-сборку: проверки не используют отключаемый `assert`.

Покрыты эталонные байты little-endian/float, короткие/повреждённые/удлинённые
пакеты, переполнение checksum, размеры payload, границы rate, FAULT/RESET,
дедупликация команд, пропуски/переупорядочивание/повторы seq и переход через ноль.

Запуск тестов ядра из консоли Visual Studio после сборки:

```bat
ctest --test-dir build -C Release -R "^unit$" --output-on-failure
```

Ожидаемый результат — тест `unit` завершён успешно. Его также можно запустить
напрямую: `build\Release\unit_tests.exe`. Для повторения проверки двух
приложений средствами Visual Studio выполнить раздел «Запуск и обязательное демо».

При подготовке этой версии дополнительно выполнен автоматический интеграционный
прогон собранных MSVC приложений: интервалы SAMPLE/HEARTBEAT, ACK/NACK, повтор
без повторного действия, FAULT, RESET, непрерывность uptime, фильтрация peer,
ретраи с тем же seq, тайм-аут, loss и CSV. Проверены чужие номера в ACK, общий
seq датчика, занятый порт, ошибка создания CSV и завершение по EOF/таймеру.
Итог проверки: **unit и integration прошли, 2/2**. Это результат полного
проверочного прогона; приведённая выше команда с `-R` запускает только `unit`.
Журналы и параметры проверенной сборки находятся в `demo/verification.txt`.
